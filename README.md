# 📊 AI-Powered Demand Forecasting — Exasol AI Build Challenge 2026

**Track:** Decision Intelligence
**Primary data platform:** Exasol Personal

## The Problem

Retailers routinely over-order slow-moving products and stock out on fast-moving
ones, especially around promotions and festive seasons. This project forecasts
daily product demand per store and turns those forecasts into concrete reorder
recommendations — the core loop of decision intelligence: **data → prediction →
action.**

## Architecture

```
retail_sales.csv ──▶ Exasol Personal (SALES_RAW table)
                          │
                          ▼
        In-database views (VW_DAILY_DEMAND, VW_WEEKLY_DEMAND,
        VW_PRODUCT_VELOCITY_30D, VW_DEMAND_ANOMALIES)
                          │
                          ▼
      Python AI layer (scripts/forecast_model.py)
      - Gradient Boosting model per store/product
      - 14-day rolling forecast
      - Reorder-point recommendation engine
                          │
                          ▼
        Streamlit dashboard (dashboard/app.py)
        - Forecast charts, KPIs, reorder table
```

Exasol is the system of record and does all heavy aggregation
(daily/weekly rollups, 30-day product velocity ranking, anomaly
detection via window functions) so the Python layer only ever
reads small, pre-aggregated result sets — this is what lets the
forecasting step stay fast even as raw sales volume grows.

## Setup & Run Guide

### 1. Install Python dependencies

```bash
pip install -r requirements.txt
```

### 2. Get Exasol Personal running

Pick whichever matches your team's setup:

- **Local (Mac/Windows/WSL/Linux, starter kit):** https://www.exasol.com/developers/
- **Local (macOS, database only):** https://www.exasol.com/personal/
- **AWS / Azure deployment:** https://github.com/exasol/exasol-personal

Once running, note the host/port and credentials.

### 3. Generate the dataset (already included, regenerate if needed)

```bash
cd scripts
python generate_data.py
```

This produces `data/retail_sales.csv` — 3 stores × 8 products × 2 years of
daily sales with trend, weekly/yearly seasonality, promotions, and stockouts.

### 4. Load data into Exasol

```bash
python load_to_exasol.py --host <your-exasol-host> --port 8563 \
    --user sys --password <your-password>
```

This runs `sql/01_schema.sql` (creates the schema, raw table, and
decision-intelligence views) and bulk-loads the CSV.

### 5. Train the forecasting model

```bash
python forecast_model.py
```

By default this reads `data/retail_sales.csv` directly for quick local
iteration. To pull from Exasol instead (recommended for the actual demo),
set connection env vars first:

```bash
export EXASOL_HOST=<your-exasol-host>
export EXASOL_PORT=8563
export EXASOL_USER=sys
export EXASOL_PASSWORD=<your-password>
python forecast_model.py
```

This trains one Gradient Boosting model per store/product pair, validates
on the last 14 days of history, then produces a 14-day forward forecast and
reorder recommendations. Outputs:
- `data/forecast_output.csv`
- `data/model_metrics.csv`
- `data/recommendations.csv`

### 6. Launch the dashboard

```bash
cd dashboard
streamlit run app.py
```

Opens at `http://localhost:8501`. Pick a store/product to see the forecast
chart, KPIs, and the full reorder recommendation table.

## Results

- Forecast accuracy: ~12–22% MAE across store/product pairs on held-out
  validation data (last 14 days) — solid for a first-pass hackathon model.
- Reorder recommendations combine forecasted lead-time demand + safety
  stock into a single actionable number per store/product.

## What Makes This "Decision Intelligence," Not Just Forecasting

The project doesn't stop at predicting numbers — `build_recommendations()`
in `forecast_model.py` converts each forecast into a concrete action
("reorder ~X units before [date]"), and `VW_DEMAND_ANOMALIES` in Exasol
flags demand spikes/drops in-database for downstream alerting. That's the
data → prediction → action loop the track calls for.
